\section*{Pytania, które mogą paść}
\begin{description}
  \item[Dlaczego czas mierzy serwis bazy, a~nie CLI?] Hop gRPC dodaje
  dziesiąte części milisekundy, czyli przy szybkich operacjach tyle samo co
  sama baza. Runner zapisuje oba czasy, porównujemy czas serwerowy.
  \item[Dlaczego brak kluczy obcych?] InnoDB tworzy indeks dla każdego FK.
  Wariant ,,bez indeksów'' w~MariaDB miałby wtedy indeksy, których
  PostgreSQL nie ma. Spójność sprawdzają testy.
  \item[Skąd pewność, że bazy mają te same dane?] Generator jest
  deterministyczny (ziarno, rodzaj, id), a~każdy import zwraca sumę
  kontrolną FNV-64. Test zgodności porównuje wyniki zapytań z~wyrocznią
  liczoną z~generatora.
  \item[Czym są ,,indeksy'' w~Valkey?] Aplikacja sama utrzymuje zbiory
  posortowane (\texttt{ix:*}). Bez nich zapytanie po atrybucie to
  \texttt{SCAN} po całej przestrzeni kluczy i~dekodowanie każdego JSON-a.
  \item[Jak wykluczono podwójną sprzedaż?] Po każdej rundzie testu
  współbieżności serwis liczy w~bazie zajęte bilety i~rezerwacje. Muszą być
  równe 500 i~liczbie udanych prób.
  \item[Czy Valkey jest uczciwie porównany?] Valkey nie zapisuje na dysk
  (bez RDB i~AOF), bazy dyskowe mają domyślną trwałość. To wyjaśnia część
  przewagi przy zapisach. Stąd w~sprawozdaniu osobny akapit o~zagrożeniach
  trafności.
  \item[Po co trace id w~wynikach?] Wolne powtórzenie z~CSV można otworzyć
  w~Jaegerze i~zobaczyć, które polecenie SQL trwało najdłużej.
\end{description}
